ASICC 자료실 3가지 오류 최소 수정 패치 (2026-11-21)

확인된 오류
1. '최근 등록 자료 5개'는 고정 문구여서, 실제 자료가 2개만 있어도 5개로 보임.
2. 신규 첨부파일 선택 시 이름은 생략되고 수량/총용량만 표시됨.
3. 개별 첨부파일 제거는 Firestore 목록에서 성공했지만 전체 게시글 삭제 시 'Failed to fetch' 오류.
   기존 Cloudflare Worker는 DELETE 요청을 처리하는 코드가 있으나,
   교차 출처 요청의 CORS 사전 확인 응답에는 DELETE가 누락돼 있음.
   따라서 전체 삭제 요청은 브라우저에서 차단될 수 있음.

수정한 코드(필요한 3개만)
- src/pages/[lang]/membres/index.astro : 실제 표시되는 최근 자료 수(0~5개)로 제목 갱신
- src/pages/[lang]/membres/[area].astro : 신규 선택 파일을 파일명/크기로 각각 표시
- worker/asicc-media-worker-extended.js : CORS 허용 메서드에 DELETE 추가
- tests/learning-ui-worker-regression.test.mjs : 새 항목 회귀검사

적용 순서
1) GitHub Desktop에서 test-cms-fr 브랜치를 선택하여 ZIP을 풀고
   src/ 및 worker/ 및 tests/ 파일을 같은 경로에 덮어쓰기.
   ZIP 자체를 저장소에 올리지 마세요.
2) Commit -> Push origin. GitHub Actions 초록색 확인.
3) Cloudflare 대시보드에서 현재 Worker 코드를 백업한 뒤,
   worker/asicc-media-worker-extended.js 내용을 붙여넣고 Deploy.
   기존 Cloudflare 환경 변수와 Secrets는 변경하지 마세요.
4) Firebase Rules 변경/재배포는 필요하지 않습니다.
5) 테스트: 자료 2개가 있으면 회원공간 '최근 등록 자료 2개' 확인,
   파일 2개 선택 시 파일명 두 줄 확인,
   첨부파일 1개 이상 있는 *테스트 글 전체 삭제* 성공 확인.

중요: 이 ZIP은 마지막 '첨부 0개 허용' 패치에서 위 변경사항만 추가한 파일입니다.
직전에 배포한 코드와 동일한 버전이라면 변경된 3개 코드 파일만 적용하세요.
Firebase/Cloudflare 실서버는 이 환경에서 테스트하지 않았으므로 배포 후 실제 동작을 확인해야 합니다.
전체 삭제가 여전히 실패하면 네트워크 오류와 Firebase 거부를 구별할 수 있도록
오류 발생한 시점의 브라우저 개발자도구 Console 문구를 확인해야 합니다.
