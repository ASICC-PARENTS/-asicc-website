[변경된 기준]
- 자료실 게시글에 첨부파일은 0~8개 가능합니다. 총 용량은 20MB 이하입니다.
- 작성자는 수정 화면에서 마지막 첨부파일까지 제거한 후, 글의 제목·본문·댓글을 유지할 수 있습니다.
- 처음부터 첨부 없이 제목/본문만으로 자료실 게시글을 등록할 수 있습니다.
- 파일 없는 글은 파일 서버 업로드 요청 없이 Firestore에 한 번에 게시합니다.
- 향후 파일을 다시 첨부할 수 있습니다.
- 게시판/갤러리 권한과 기존 사진 업로드 API는 변경하지 않습니다.

[사용할 파일]
- src/pages/[lang]/membres/[area].astro : 첨부파일 필수 해제, 저장·편집·표시
- src/pages/[lang]/membres/index.astro : 직전 패치의 최근 등록 자료 갱신 유지
- firestore.rules.PROPOSED_ONLY : 빈 첨부목록과 총용량 0 허용, 작성자 권한 유지
- worker/asicc-media-worker-extended.js : 빈 첨부목록 글에서도 개별 저장파일 삭제·재첨부 처리
- tests/media-rules.test.mjs, tests/patch-regressions.test.mjs : 보안·회귀 검증

[적용 순서]
1) GitHub Desktop -> test-cms-fr 브랜치에 ZIP의 위 파일을 동일 경로로 복사 -> Commit -> Push origin.
2) GitHub Actions 초록색 확인 (특히 Firestore emulator 관련 테스트).
3) Firebase Console -> Firestore Database -> Rules: 현재 규칙 백업 후 ZIP의 firestore.rules.PROPOSED_ONLY 내용 확인·Publish.
   이 제안 규칙은 앞서 ASICC에서 사용하던 통합 규칙을 바탕으로 한 파일입니다.
   Firebase 규칙에 이후 별도 수정이 있었다면 전체 덮어쓰지 말고 해당 수정사항을 먼저 합치세요.
4) Cloudflare -> 기존 ASICC Worker 코드 백업 -> ZIP의 worker/asicc-media-worker-extended.js 코드 적용 -> Deploy.
   환경변수/비밀키는 변경하지 않습니다.
5) 이미 있는 테스트 게시글에서 마지막 파일을 제거 후 저장 -> 본문/댓글 유지 여부 확인.
   다음으로 해당 게시글에 새 파일 추가와, 처음부터 파일 없이 글 등록을 확인하세요.
